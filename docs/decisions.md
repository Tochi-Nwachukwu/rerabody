# Decisions log

Choices made where the build plan was silent or a dependency forced a change. Newest phase last.

## Phase 0

| Topic | Decision | Why |
| --- | --- | --- |
| TypeScript version | TypeScript 6.0.x, not 7.0 | `typescript-eslint` (used by `eslint-config-next`) supports TypeScript below 6.1 only. Upgrade when it supports 7 |
| ESLint version | ESLint 9, as installed by `create-next-app` 16.4 | ESLint 10 is out, but the Next.js scaffold still pins 9 |
| Prisma version | Prisma ORM 7.10.1 | The npm `latest` tag points at an 8.0 release candidate. Better Auth's Prisma adapter does not support Prisma 8 yet |
| Prisma config file | `prisma7.config.ts` | Name generated by `prisma init` in 7.10. Earlier 7.x used `prisma.config.ts` |
| Pooled and direct URLs | CLI uses `DIRECT_URL` (set in `prisma7.config.ts`); the app passes the pooled `DATABASE_URL` to the `pg` driver adapter in `src/server/prisma.ts` | Prisma 7 removed `directUrl` from the schema |
| `db:migrate` script | `prisma migrate deploy` (applies committed migrations, never prompts). `db:migrate:dev` runs `prisma migrate dev` for authoring new migrations | Safe on CI and production, and runs clean on an empty database |
| Product search vector | Plain `tsvector` column kept current by a `BEFORE INSERT OR UPDATE` trigger, with a GIN index. Name weighted A, Tiptap description text weighted B | A generated column shows up as permanent drift in Prisma Migrate (it tries to drop the expression as a default) |
| Trigram index | `Product_name_trgm_idx`, GIN on `name gin_trgm_ops`, declared in the schema with `ops: raw(...)`. The extension itself is created in the migration SQL | Avoids the `postgresqlExtensions` preview feature |
| Database CHECK constraints | `stock >= 0`, `price >= 0`, cart and order item `quantity > 0`, review `rating` 1 to 5 | Backstop for rules 3 and 9 in addition to the service checks |
| IDs | `cuid()` string ids on every model, including the Better Auth tables | One id format. Better Auth still supplies its own ids when it creates rows |
| Table names | Prisma model names (PascalCase), including Better Auth tables (no `@@map("user")`) | Consistency. The adapter addresses models by client name, not table name |
| Extra fields not in section 7 | `Order.needsManualReview`, `Order.manualReviewReason`, `Order.paidAt`, `OrderItem.productId`, `User.image` (Better Auth) | Rule 3 asks for a manual-review flag. `paidAt` drives reports. `productId` keeps reviews and reports working after a variant is deleted |
| Nullable `HomeSection.data` | `data` is nullable | A section added in the editor exists only as a draft until first publish |
| Media protection | Every foreign key to `Media` uses `onDelete: Restrict` | Rule 11 at the database level. JSON references (homepage sections) are checked in the media service in Phase 2 |
| Role defaults | Owner: all. Manager: everything except `orders.refund`, `staff.manage`, `roles.manage`, `settings.manage`, `audit.read`. Inventory staff: products, inventory, `media.upload`. Fulfilment staff: `orders.read`, `orders.update`. Content editor: `content.manage`, `media.upload`, `media.delete` | build-plan.md lists refunds, staff, roles and settings as Owner-only. Manager gets `support.manage` with customers. Inventory staff need uploads for product images |
| `Role.isSystem` | Only Owner is seeded as a system role | Rule 14 protects Owner. Other roles stay editable in A26 |
| Caching | `cacheComponents: true` (Next.js 16 Cache Components) | Tag revalidation (`cacheTag`, `revalidateTag`) is the current Next.js caching model for the tag scheme in section 4 |
| Placeholder currency | Local `.env` uses `GBP` | Placeholder only. Real currency is an open question for the client |
| Section data shapes | Seeded homepage section `data` is provisional | The Zod schema per section type is written in Phase 6. The seed will be aligned then |
| Owner credential | Seed writes the owner's Better Auth `credential` account with `hashPassword` from `better-auth/crypto`, `accountId` = user id | Same shape as Better Auth sign-up, so the owner can sign in once auth is wired in Phase 1 |
