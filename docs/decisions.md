# Decisions log

Choices made where the build plan was silent or a dependency forced a change. Newest phase last.

## Phase 0

| Topic | Decision | Why |
| --- | --- | --- |
| TypeScript version | TypeScript 6.0.x, not 7.0 | `typescript-eslint` (used by `eslint-config-next`) supports TypeScript below 6.1 only. Upgrade when it supports 7 |
| ESLint version | ESLint 9, as installed by `create-next-app` 16.4 | ESLint 10 is out, but the Next.js scaffold still pins 9 |
| Prisma version | Prisma ORM 7.10.1 | The npm `latest` tag points at an 8.0 release candidate. Better Auth's Prisma adapter does not support Prisma 8 yet |
| Prisma config file | `prisma7.config.ts` | Name generated by `prisma init` in 7.10. Earlier 7.x used `prisma.config.ts` |
| Pooled and direct URLs | CLI uses `DIRECT_URL` (set in `prisma7.config.ts`); the app passes the pooled `DATABASE_URL` to the `pg` driver adapter in `src/server/prisma.ts` | Prisma 7 removed `directUrl` from the schema |
| `db:migrate` script | `prisma migrate deploy` (applies committed migrations, never prompts). `db:migrate:dev` runs `prisma migrate dev` for authoring new migrations | Safe on CI and production, and runs clean on an empty database |
| Product search vector | Plain `tsvector` column kept current by a `BEFORE INSERT OR UPDATE` trigger, with a GIN index. Name weighted A, Tiptap description text weighted B | A generated column shows up as permanent drift in Prisma Migrate (it tries to drop the expression as a default) |
| Trigram index | `Product_name_trgm_idx`, GIN on `name gin_trgm_ops`, declared in the schema with `ops: raw(...)`. The extension itself is created in the migration SQL | Avoids the `postgresqlExtensions` preview feature |
| Database CHECK constraints | `stock >= 0`, `price >= 0`, cart and order item `quantity > 0`, review `rating` 1 to 5 | Backstop for rules 3 and 9 in addition to the service checks |
| IDs | `cuid()` string ids on every model, including the Better Auth tables | One id format. Better Auth still supplies its own ids when it creates rows |
| Table names | Prisma model names (PascalCase), including Better Auth tables (no `@@map("user")`) | Consistency. The adapter addresses models by client name, not table name |
| Extra fields not in section 7 | `Order.needsManualReview`, `Order.manualReviewReason`, `Order.paidAt`, `OrderItem.productId`, `User.image` (Better Auth) | Rule 3 asks for a manual-review flag. `paidAt` drives reports. `productId` keeps reviews and reports working after a variant is deleted |
| Nullable `HomeSection.data` | `data` is nullable | A section added in the editor exists only as a draft until first publish |
| Media protection | Every foreign key to `Media` uses `onDelete: Restrict` | Rule 11 at the database level. JSON references (homepage sections) are checked in the media service in Phase 2 |
| Role defaults | Owner: all. Manager: everything except `orders.refund`, `staff.manage`, `roles.manage`, `settings.manage`, `audit.read`. Inventory staff: products, inventory, `media.upload`. Fulfilment staff: `orders.read`, `orders.update`. Content editor: `content.manage`, `media.upload`, `media.delete` | build-plan.md lists refunds, staff, roles and settings as Owner-only. Manager gets `support.manage` with customers. Inventory staff need uploads for product images |
| `Role.isSystem` | Only Owner is seeded as a system role | Rule 14 protects Owner. Other roles stay editable in A26 |
| Caching | `cacheComponents: true` (Next.js 16 Cache Components) | Tag revalidation (`cacheTag`, `revalidateTag`) is the current Next.js caching model for the tag scheme in section 4 |
| Placeholder currency | Local `.env` uses `GBP` | Placeholder only. Real currency is an open question for the client |
| Section data shapes | Seeded homepage section `data` is provisional | The Zod schema per section type is written in Phase 6. The seed will be aligned then |
| Owner credential | Seed writes the owner's Better Auth `credential` account with `hashPassword` from `better-auth/crypto`, `accountId` = user id | Same shape as Better Auth sign-up, so the owner can sign in once auth is wired in Phase 1 |

## Phase 1

| Topic | Decision | Why |
| --- | --- | --- |
| Screen map | `docs/screen-map.md` was not supplied. Screens follow the flows in `build-plan.md`. Routes chosen: A1 `/admin/login`, A2 `/admin/accept-invite`, A3 `/admin`, S13 `/login`, S14 `/register`, S15 `/verify-email`, S16 `/forgot-password`, S17 `/reset-password` | Needed to build the screens. Easy to rename when the screen map arrives |
| Email transport | `EMAIL_TRANSPORT=log` writes emails to `.emails/outbox.jsonl` instead of calling Resend. Default is `resend` | Local work and Playwright need to read verification links without a Resend account |
| Email retries | If a dedupe key's earlier send FAILED, the next call with that key claims the row and retries. Any other existing status is a duplicate | build-plan.md asks to "retry failures" without breaking rule 6 |
| Auth emails not awaited | Verification and reset sends are fired without `await` | Better Auth guidance: avoids timing differences that reveal whether an account exists (rule 13) |
| Rate limiting | Better Auth's built-in limiter with database storage (`RateLimit` table). Sign in and sign up 5 per minute, reset and verification resend 3 per minute | Phase 9 asks for it; the auth routes are covered now because the limiter is part of the auth config |
| Deactivated users | Blocked from creating a session (Better Auth session hook) and treated as signed out by `getSession` | Covers existing sessions too |
| Sign-up role | A `user.create.before` hook forces `roleId = null` and `status = ACTIVE` | Sign-up can never create staff |
| Admin refusal | A signed-in customer at `/admin` is sent to `/admin/login?error=no-access`, which offers sign out | "A customer account is refused at `/admin`" |
| Page permission refusal | Admin pages call `requirePagePermission`, which redirects to the dashboard with a notice | Actions use `requirePermission`, which throws `AuthError` |
| Test databases | `TEST_DATABASE_URL` for Vitest (truncated between tests, files run one at a time) and `E2E_DATABASE_URL` for Playwright (migrated and seeded before each run) | Integration tests need a real Postgres for unique constraints and conditional writes |
| Prisma generate | `db:migrate:dev` runs `prisma generate` after migrating | Prisma 7 `migrate dev` no longer regenerates the client |

## Phase 2

| Topic | Decision | Why |
| --- | --- | --- |
| Admin routes | A4 `/admin/products`, A5 `/admin/products/new` and `/admin/products/[id]`, A6 `/admin/categories`, A7 `/admin/collections`, A8 `/admin/inventory`, A24 `/admin/media` | No screen map |
| Upload flow | Browser asks `/api/uploads/presign` for a key and signed URL, PUTs the file straight to R2 with progress, then calls `registerUploadAction`, which checks the stored object's size and type with a HEAD request before creating the `Media` row | The presign route cannot see the bytes. The HEAD check enforces the 8 MB cap and type even if the client misbehaves |
| Signed headers | The R2 presigned PUT signs `content-type` and `content-length` | The client cannot change the type or size after presigning |
| R2 CORS | The bucket needs a CORS rule allowing PUT from the store origin (documented in deploy.md in Phase 9) | Browser uploads go directly to R2 |
| Local storage driver | `STORAGE_DRIVER=local` keeps files in `.uploads/`, with an HMAC-signed PUT route and a GET route under `/api/uploads/local` (both 404 unless the driver is local) | Lets the admin and Playwright upload without R2 credentials |
| Media references | Rule 11 is enforced by `onDelete: Restrict` foreign keys plus a text search of homepage section JSON and site settings | Sections reference media inside JSON, which a foreign key cannot cover |
| Product editor form | Controlled state validated with the shared `productSchema` before submit; the server validates the same schema. Simpler forms use React Hook Form | The editor has nested, generated variant rows that change with the options |
| Stock on edit | Saving a product never changes stock on existing variants. New variants take an opening stock recorded as a RESTOCK movement. Other changes go through A8 | Every stock change has a movement row |
| Removed variants | Deleted if never ordered, otherwise deactivated and their SKU suffixed `-RETIRED-…` | Order history keeps its variant link |
| Product delete | Allowed only for products never ordered; otherwise archive | "Archiving hides a product without deleting its order history" |
| Category delete | Refused while products use it | Avoids silently uncategorised products |
| Variant options | Up to three options, values entered as comma-separated text | Simple and accessible |
| Inventory adjust | Add, remove or set to. Restock must add, damage must remove, correction either way. "Set to" uses an optimistic check against the stock read, so a sale in between is not overwritten | Rule 3 spirit: stock never negative, no lost updates |
| Unique errors | With Prisma 7 driver adapters the constraint name is in `meta.driverAdapterError`; `uniqueViolationOn()` checks the serialised meta | `meta.target` is no longer set |
| Cache invalidation | `expireTags()` calls `revalidateTag(tag, { expire: 0 })` | Works in both Server Actions and route handlers (webhooks) |
